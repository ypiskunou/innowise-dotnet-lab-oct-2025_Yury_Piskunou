# Консольное приложение "Менеджер Задач"

Это учебный проект, демонстрирующий создание консольного приложения на .NET с использованием профессиональных архитектурных подходов. Цель проекта — не просто выполнить задание, а построить гибкую, расширяемую и тестируемую систему.

## Основные технологии

- **Язык:** C# 10+

- **Платформа:** .NET 6+

- **Доступ к данным:** Dapper (микро-ORM)

- **Базы данных:** Поддержка PostgreSQL и MS SQL Server.

- **Архитектура:** Принципы Чистой Архитектуры (Clean Architecture), Dependency Injection (DI).

- **Тестирование:** xUnit, Moq, FluentAssertions.


## Архитектурные решения

Проект построен на основе многослойной архитектуры для достижения **низкой связанности** и **высокой тестируемости**.

### Структура решения (.sln)

Решение разделено на несколько проектов, каждый из которых имеет свою зону ответственности:

- TaskManager.Domain: **Ядро** приложения. Содержит бизнес-сущности (TaskItem) и "контракты" (интерфейсы, например ITaskRepository). Этот проект не зависит ни от чего.

- TaskManager.Application: **Логика** приложения. Содержит сервисы (TaskApplicationService) и команды (IAsyncCommand), которые реализуют бизнес-правила. Зависит только от Domain.

- TaskManager.Repository: **Репозиторий**. Содержит конкретные реализации для работы с внешним миром: репозитории для PostgreSQL и MS SQL, фабрики подключений. Зависит только от Domain.

- TaskManager.ConsoleApp: **Точка входа** и UI. Отвечает за отображение меню, чтение ввода пользователя и **сборку** всего приложения с помощью DI-контейнера. Зависит от Application и Repository.

- TaskManager.Tests: **Тесты**. Содержит Unit-тесты для слоя Application и Интеграционные тесты для слоя Repository, обеспечивая надежность кода.


### Ключевые паттерны и решения

#### 1. Паттерн "Репозиторий" и "Фабрика"

Для работы с базой данных используется паттерн **Репозиторий** (ITaskRepository). Это позволяет слою Application работать с данными, не зная, где они хранятся (в PostgreSQL, MS SQL или где-то еще). Для создания подключений к БД используется простая **Фабрика** (IDbConnectionFactory), что позволяет легко подменять типы баз данных.

#### 2. Паттерн "Команда" вместо switch-case

Для обработки действий пользователя в меню используется паттерн **Команда**. Вместо громоздкого и негибкого switch-case в коде, у нас есть набор классов-команд (например, ShowAllTasksCommand), каждый из которых отвечает за одно действие.

**Преимущества:**

- **Расширяемость:** Чтобы добавить новый пункт меню, достаточно создать новый класс-команду. Код основного цикла приложения (ConsoleWorker) при этом не меняется.

- **Принцип Единой Ответственности:** Каждый класс решает одну-единственную, маленькую задачу.


#### 3. Гибкий выбор базы данных ("Регистраторы")

В Program.cs реализован механизм, который позволяет переключаться между PostgreSQL и MS SQL Server, просто изменив одну строчку в файле appsettings.json.

**"Извинение" за сложность Registrar'ов:**

> На первый взгляд, создание интерфейса IDatabaseRegistrar и отдельных классов для каждой СУБД может показаться избыточным усложнением. Почему бы просто не использовать if или switch в Program.cs?
>
> Ответ кроется в **Принципе Открытости/Закрытости**. Текущая архитектура позволяет добавить поддержку новой базы данных (например, Oracle или SQLite), **не изменяя существующий, уже отлаженный код Program.cs**. Нам достаточно будет лишь добавить новый класс-регистратор. В больших проектах, где любое изменение несет в себе риск, такая "закрытость" для изменений является золотым стандартом надежности и поддержки. Мы платим небольшую цену в виде дополнительного класса, но выигрываем в гибкости и безопасности в долгосрочной перспективе.

## Тестирование

Проект содержит два вида тестов, демонстрирующих профессиональный подход к обеспечению качества:

- **Unit-тесты** (TaskApplicationServiceTests): Проверяют бизнес-логику сервисов в полной изоляции от базы данных с помощью "фейковых" репозиториев (Moq). Эти тесты молниеносно быстрые.

- **Интеграционные тесты** (PostgreSqlTaskRepositoryTests, MsSqlTaskRepositoryTests): Проверяют, что репозитории корректно работают с **реальной** (тестовой) базой данных. Они гарантируют, что SQL-запросы написаны правильно и совместимы с выбранной СУБД.


## Как запустить

1. **Настройте appsettings.json:** В проекте TaskManager.ConsoleApp укажите в файле appsettings.json (или в secrets.json для локальной разработки) ваши строки подключения.

2. **Создайте базу данных:** Выполните SQL-скрипты из папки DatabaseScripts для создания и наполнения вашей базы данных (PostgreSQL или MS SQL).

3. **Запустите приложение:** Установите TaskManager.ConsoleApp в качестве запускаемого проекта и запустите его.
